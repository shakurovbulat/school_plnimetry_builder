# Финальные пользовательские сценарии (User Scripts)

### Проект: «Построитель чертежей для школьной планиметрии» (GeoSolver)
### Автор: Булат Шакуров (Группа 10И2)
### Репозиторий: https://github.com/shakurovbulat/school_plnimetry_builder

---

## 1. Сценарий: Ввод и валидация условия задачи на естественном языке
* **Пользователь открывает** веб-интерфейс приложения Streamlit в браузере.
* **Пользователь вводит** текстовое условие планиметрической задачи (например, *«В прямоугольном равнобедренном треугольнике ABC гипотенуза AB равна 14 см. Из точки F опущены перпендикуляры FM и FN»*) либо выбирает готовый шаблонный пример.
* **Пользователь нажимает** кнопку «Построить».
* **Клиент Streamlit проверяет**, что строка ввода не пуста; при пустом вводе выводится предупреждение: *«Введите условие задачи»*.
* **Клиент отправляет** HTTP POST-запрос на эндпоинт FastAPI `/solve` с телом `{"text": "<текст задачи>"}`.
* **Интерфейс отображает** индикатор ожидания (spinner) во время парсинга и расчёта координат.

---

## 2. Сценарий: Лингвистический и геометрический парсинг текста
* **Бэкенд-сервис принимает** входящий запрос в функции `solve_geometry_task` (`backend/main.py`).
* **Модуль `backend/parser.py` выполняет** предварительную нормализацию: заменяет визуально совпадающие кириллические заглавные буквы (А, В, С, Е, М, Н, К, Т, Х, Р, О) на соответствующие латинские символы вершин (A, B, C, E, M, N, K, T, X, P, O).
* **Парсер извлекает**:
  * Имена вершин и точек (регулярные шаблоны `[A-Z]`).
  * Многоугольники и отрезки (треугольники `[A-Z]{3}`, отрезки `[A-Z]{2}`).
  * Числовые величины длин и градусных мер углов.
  * Специальные свойства фигур (прямоугольный, равнобедренный, равносторонний треугольник).
  * Конструктивные отношения (перпендикуляры, основания высот, принадлежность точки отрезку).
  * Целевые вопросы задачи (поиск отрезков, углов или площадей).
* **Парсер возвращает** структурированный словарь `parser_data` с полным списком геометрических ограничений (`constraints`).

---

## 3. Сценарий: Автоматический расчёт координат (Геометрический солвер)
* **Модуль `backend/solver.py` принимает** результат разбора `parser_data`.
* **Солвер формирует** перечень уникальных точек задачи и накладывает систему геометрических ограничений:
  * Фиксация базовых точек для устранения степеней свободы сдвига и вращения чертежа.
  * Формирование функций невязки для длин отрезков, равенств сторон, прямых углов и проекций точек.
* **Солвер выполняет** численную минимизацию функции невязок (SciPy / численный алгоритм оптимизации), находя координаты $(x_i, y_i)$ для каждой вершины.
* **Солвер формирует** список соединяющих линий (`lines`) и диагностическую информацию (`diagnostics`: статус сходимости, значение ошибки, число итераций).
* **Бэкенд возвращает** клиенту единый JSON-ответ со статусом `"success"`, массивами точек, линий и метаданными.

## 4. Сценарий: Визуализация интерактивного чертежа и аналитики
* **Streamlit-клиент принимает** сформированный JSON-ответ.
* **Функция `draw_schema` строит чертёж** средствами Matplotlib:
  * Синими сплошными линиями соединяются смежные вершины многоугольников и построенные проекции/перпендикуляры.
  * Вершины выделяются контрастными маркерами с аккуратным смещением текстовых подписей (A, B, C, F, M, N).
  * Применяется пропорциональный масштаб (`aspect="equal"`) и отступы, предотвращающие обрезание меток.
* **В правой аналитической панели отображаются**:
  * Диагностические метрики сходимости солвера.
  * Сводка найденных фигур, условий и целевых параметров.
  * По запросу (флаг *«Показывать JSON парсера»*) доступен полный структурированный JSON для разработчика и учителя.

## 5. Сценарий: Массовое регрессионное тестирование и калибровка
* **Разработчик/исследователь запускает** утилиту регрессионного тестирования:
  ```bash
  python backend/test_runner.py --limit 50
  ```
* **Скрипт считывает** массив реальных задач из `exercises.json` (сформированный, в том числе, парсером учебника `uchebnik_parser.py` по школьным пособиям).
* **Тест-раннер прогоняет** формулировки через `parse_geometry_text`, валидирует корректность извлечения точек, линий, фигур и ограничений, и выводит отчёт в консоль.
* **Разработчик анализирует** краевые случаи и дополняет словарь синтаксических шаблонов парсера.

---

## 6. Сценарий: Обработка ошибок и непредвиденных ситуаций
* **Случай отсутствия связи с сервером:**
  Если FastAPI не запущен, клиент Streamlit перехватывает `requests.exceptions.ConnectionError` и выводит пользователю информативное уведомление: *«Не удалось подключиться к FastAPI. Запустите backend/main.py на порту 8000»*.
* **Случай задачи без геометрических точек:**
  Если в тексте не распознано ни одной вершины, интерфейс предупреждает: *«Парсер не нашел точек для построения»*, предотвращая падение приложения.
* **Случай некорректных или несовместных ограничений:**
  Солвер возвращает диагностику качества сходимости (`diagnostics`), позволяя пользователю увидеть, какие именно условия вызвали перегрузку системы ограничений.
