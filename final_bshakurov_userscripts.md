# Пользовательские сценарии для проекта «Построитель чертежей для школьной планиметрии»

### Группа: 10И2
### Электронная почта: brshakurov@edu.hse.ru
### ТГ: @shakurov_bulat

Актуальные сценарии реализованной локальной версии. Первоначальный документ сохранён в `OLD/bshakurov_userscripts.md`. Сценарии описывают фактическое поведение, а не обещание поддержки произвольных условий.

**[ ПОДГОТОВКА К РАБОТЕ ]**

- **Пользователь устанавливает** зависимости Python и Ollama, загружает модель и создаёт `.env` по `.env.example` согласно `README.md`.
- **Пользователь запускает** `python launch.py` из корня и открывает http://127.0.0.1:8501.
- **Система запускает** отдельные API и Streamlit на loopback. Облачный ключ не нужен.
- **Пользователь при необходимости выбирает** другую установленную модель через `OLLAMA_MODEL` либо явно включает `PARSER_MODE=rules` и перезапускает API.
- **Система не переключается** на правила незаметно при недоступности Ollama.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 1: ВВОД УСЛОВИЯ ЗАДАЧИ НА ЕСТЕСТВЕННОМ ЯЗЫКЕ ]**

- **Пользователь вводит** русскоязычное условие в поле «Условие задачи» либо выбирает пример и нажимает «Загрузить пример».
- **Пользователь нажимает** «Сгенерировать чертёж».
- **Система показывает** индикатор распознавания и проверки геометрии и отправляет запрос `/solve`.
- **Система проверяет** непустой ввод, предел 6000 символов и отсутствие запрещённых управляющих символов.
- **Система предупреждает** «Поле ввода не может быть пустым» при пустой строке. Остальные ошибки API показываются вместе с сообщением о невозможности построения.
- **Если пользователь меняет текст** после успешной генерации, система предупреждает, что на экране прежний чертёж. Автоматической генерации на каждое нажатие клавиши нет.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 2: РАСПОЗНАВАНИЕ ГЕОМЕТРИЧЕСКИХ ОБЪЕКТОВ ]**

- **Система нормализует** поддержанные смешанные обозначения и формирует предварительную схему правил.
- **В режиме Ollama система запрашивает** JSON по схеме, валидирует ответ и сохраняет поддержанные детерминированные конструкции. Конфликт явных числовых фактов отклоняется.
- **Система проверяет** уникальность имён и ссылки на точки в отрезках, фигурах, окружностях и ограничениях. Схема допускает буквенные имена с индексом до 999, но их распознавание из произвольного текста ограничено.
- **Система показывает** распознанные точки и фигуры рядом с чертежом; в раскрывающемся блоке подсвечивает совпадающие обозначения и числа.
- **Пользователь сверяет** список с исходным условием. Подсветка не является доказательством полноты распознавания.
- **При отсутствии поддержанной геометрии** система сообщает об ошибке, а не строит выдуманный треугольник.
- Дуги не представлены универсальными самостоятельными объектами: отдельные поддержанные условия переводятся в угловые ограничения.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 3: РАСПОЗНАВАНИЕ ЧИСЛОВЫХ ПАРАМЕТРОВ ]**

- **Система извлекает** поддержанные длины, углы, радиусы, периметры, отношения и тригонометрические значения.
- **Система нормализует** поддержанные дроби, корни и десятичные запятые безопасным арифметическим разбором, без выполнения кода пользователя.
- **Система проверяет** конечность чисел, положительность длин/радиусов и допустимые диапазоны углов и отношений.
- **Система выводит** параметры вместе с объектами в разделе «Параметры и отношения».
- **При неоднозначном или неверном вводе пользователь уточняет** исходный текст и повторяет генерацию. Отдельного диалога ручной подстановки неоднозначного числа в интерфейсе нет.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 4: РАСПОЗНАВАНИЕ ГЕОМЕТРИЧЕСКИХ ОТНОШЕНИЙ ]**

- **Система связывает** объекты ограничениями параллельности, перпендикулярности, равенства, принадлежности, середины, проекции, биссектрисы и поддержанных окружностных конструкций.
- **Система отделяет** распознанные просьбы доказать утверждение от исходных данных, чтобы не использовать заключение как предпосылку.
- **Система проверяет** схему и численные невязки построения. Известные неподдержанные конфигурации отклоняются явно; неизвестное ограничение не считается успешно выполненным.
- **Пользователь изучает** список отношений справа и при необходимости уточняет текст.
- **Система не гарантирует** обнаружение всех пропущенных деталей произвольного текста: контроль полноты эвристический, а не универсальный.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 5: АВТОМАТИЧЕСКАЯ ГЕНЕРАЦИЯ КООРДИНАТ ОБЪЕКТОВ ]**

- **Система формирует** ограничения и ищет координаты с помощью SymPy, NumPy и SciPy.
- **Система проверяет** невырожденность, явные противоречия длин и неравенство треугольника; допустимость решения определяется численной невязкой.
- **Если размеры заданы не полностью**, система выбирает один допустимый экземпляр в удобном масштабе. Он не объявляется единственным или доказательством задачи.
- **Система возвращает** координаты, объекты и диагностику через API.
- **При неудаче поиска** система выдаёт ошибку с предложением уточнить условия; не всякий численный отказ означает математическую невозможность.
- **При недоступной Ollama** API возвращает 503, при некорректных данных/неудачном построении — 422. Интерфейс показывает сообщение об ошибке.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 6: ПОСТРОЕНИЕ ИНТЕРАКТИВНОГО ЧЕРТЕЖА ]**

- **Система отображает** на Canvas точки с подписями, отрезки, окружности и маркеры заданных углов.
- **Система центрирует** новое построение в области просмотра, включая окружности.
- **Система показывает** предупреждения о свободных параметрах и неоднозначных ветвях для соответствующих конфигураций.
- **Пользователь сверяет** рисунок и распознанные отношения с условием.
- **При неудаче новой генерации** старое решение убирается из активного отображения, чтобы не принять его за результат нового запроса.
- Интерактивность реализована Canvas-компонентом, а не интерактивным Matplotlib-контейнером. Matplotlib используется при экспорте.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 7: МАСШТАБИРОВАНИЕ И ПЕРЕМЕЩЕНИЕ ЧЕРТЕЖА ]**

- **Пользователь прокручивает** колесо мыши над холстом для изменения масштаба относительно указателя.
- **Пользователь перетаскивает** фон для перемещения вида.
- **Пользователь нажимает** «Сбросить вид», чтобы вернуть автоматический охват всего построения.
- **Система ограничивает** чрезмерное приближение и удаление, не изменяя математические координаты.
- **Система обрабатывает** pinch двух указателей. Проверки wheel/pan/reset выполнены в Chrome; физический pinch на устройстве остаётся ручной проверкой.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 8: РЕДАКТИРОВАНИЕ ПОЛОЖЕНИЯ ТОЧЕК ВРУЧНУЮ ]**

- **Пользователь захватывает** маркер точки и перетаскивает его; система выделяет его цветом.
- **Во время движения система показывает** локальное предварительное положение, без полного серверного решения на каждом кадре.
- **После отпускания система отправляет** имя и новые координаты в `/update-point`; до принятия сервером сохраняются исходные подтверждённые данные.
- **Сервер фиксирует** новое положение выбранной точки и пересчитывает остальные, сохраняя ограничения. Свободные вершины тоже могут переместиться.
- **При успехе система обновляет** чертёж и сохраняет контекст распознавания и предупреждения.
- **При отказе система показывает** предупреждение и оставляет прежний чертёж.
- Изменения точек отдельно в историю не записываются; пользователь может экспортировать отредактированный результат.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 9: ЭКСПОРТ РЕЗУЛЬТАТА В PNG И SVG ]**

- **Пользователь нажимает** «Скачать PNG» или «Скачать SVG» под холстом; отдельного выпадающего меню нет.
- **Система формирует** изображение Matplotlib из подтверждённой геометрии, а не снимок текущего zoom/pan.
- **Система предлагает** браузерное скачивание с именем `geometry_drawing_YYYYMMDD_HHMMSS.png` или `.svg`; PNG сохраняется с 300 DPI.
- **При использовании API экспорта** сервер дополнительно проверяет переданные координаты и отклоняет нарушенные ограничения.
- Отказ браузера записать файл не может надёжно перехватываться стандартной кнопкой Streamlit; при такой ошибке пользователь проверяет разрешения и каталог загрузки браузера.

**[ ДОПОЛНИТЕЛЬНЫЙ СЦЕНАРИЙ: ИСТОРИЯ ПОСТРОЕНИЙ ]**

- **Система сохраняет** успешную генерацию, исходный текст и результат в `data/history.sqlite3`.
- **Пользователь нажимает** «Обновить историю», выбирает запись и нажимает «Открыть построение».
- **Система восстанавливает** текст и сохранённый чертёж без нового обращения к LLM.
- **Если история недоступна**, интерфейс предупреждает пользователя. Ошибка записи истории после построения не мешает экспортировать полученный чертёж.
- История локальная и не включается в Git. Для публичного использования нужны отдельные меры защиты и авторизация, которых текущая версия не предоставляет.
