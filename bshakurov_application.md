**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

Проблемное поле
При решении задач по планиметрии учащиеся и преподаватели регулярно сталкиваются со следующими проблемами:
Высокие временные затраты на построение чертежей.
По наблюдениям на уроках геометрии, ручное построение аккуратного и корректного чертежа к задаче в среднем занимает от 5 до 15 минут, что составляет значительную часть времени урока или самостоятельной работы и снижает эффективность решения.
Сложность интерпретации текстового условия.
Даже при наличии верного чертежа ученики часто ошибаются на этапе переноса условия задачи в графическое представление: неверно выбирают взаимное расположение точек, углов и отрезков, из-за чего дальнейшее решение становится затруднительным или ошибочным.
Недостаточная наглядность чертежей.
Ручные чертежи часто получаются неточными, несоразмерными или перегруженными, что затрудняет выявление ключевых свойств (равенства, параллельности, перпендикулярности).
Следствием этих проблем является потеря времени, снижение понимания материала и рост количества ошибок при решении задач.

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ ]**

Ввод условия задачи на естественном языке.
Распознавание геометрических объектов (точки, отрезки, углы, окружности).
Распознавание числовых параметров (длины, углы).
Распознавание геометрических отношений (параллельность, перпендикулярность, равенство).
Автоматическая генерация координат объектов.
Построение интерактивного чертежа.
Масштабирование и перемещение чертежа.
Редактирование положения точек вручную.
Экспорт результата в PNG и SVG.

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

Похожие / аналогичные продукты
GeoGebra
Требует ручного построения каждого объекта.
Пользователь должен заранее понимать, как именно строить чертёж.
Не работает напрямую с текстовым условием задачи, что делает его неудобным для быстрого старта.

Desmos Geometry
Ограниченный набор геометрических инструментов.
Отсутствует поддержка сложных школьных конструкций (медианы, высоты, биссектрисы как сущности).
Также не поддерживает ввод условия на естественном языке.

Чертежи в тетради / на доске
Занимают значительное время.
Часто получаются неточными и плохо масштабируемыми.
Невозможен быстрый повторный показ или перенос в цифровой формат.

Вывод: существующие решения либо требуют высокой подготовки пользователя, либо не ориентированы именно на школьные задачи, сформулированные текстом.

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ ]**

Проект реализуется на языке Python с логическим разделением на серверную (backend) и пользовательскую (frontend) части, взаимодействующие между собой через HTTP API.

Backend (серверная часть)
Серверная часть отвечает за:
разбор текстового условия задачи,
геометрические вычисления,
формирование формального описания чертежа.

Технологии backend:
Python
FastAPI — используется для реализации REST API. Выбран из-за высокой производительности, строгой типизации и удобной документации.
SymPy — применяется для точных геометрических вычислений (точки, прямые, окружности, углы).
Natasha — используется для извлечения именованных сущностей, чисел и ключевых геометрических терминов из текста задачи.
SQLAlchemy (ORM) — для работы с базой данных без ручного написания SQL-запросов.
SQLite — используется как СУБД на этапе учебного проекта из-за простоты развёртывания.
API принимает текст задачи и возвращает JSON-описание геометрических объектов, их координат и связей.

Frontend (клиентская часть)
Клиентская часть отвечает за:
ввод текста задачи,
отправку запроса на backend,
визуализацию полученного чертежа.

Технологии frontend:
Streamlit — используется для создания веб-интерфейса. Выбран, так как позволяет быстро реализовать UI без глубокого изучения фронтенд-фреймворков.
Matplotlib — применяется для отрисовки чертежей на основе данных, полученных от backend.
Streamlit выступает как отдельный клиент, который не содержит логики анализа задач, а только взаимодействует с API.
