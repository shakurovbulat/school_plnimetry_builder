**[ НАЗВАНИЕ ПРОЕКТА ]**

«Построитель чертежей для школьной планиметрии».

**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

Перенос текстового условия в аккуратный чертёж требует времени и понимания взаимного расположения объектов. Приложение формализует условие с помощью языковой модели, строит численную геометрическую конфигурацию и позволяет проверить, отредактировать и экспортировать результат.

Это не универсальный решатель: приложение не выдаёт доказательств и не гарантирует полное распознавание любого условия. Пользователь должен сверять объекты и отношения с исходным текстом.

**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**

- Учащиеся 7–11 классов, изучающие планиметрию.
- Учителя математики и репетиторы, готовящие иллюстрации.
- Пользователи, которым нужен школьный чертёж в цифровом виде.

**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]**

- Python с поддержкой зависимостей из `requirements.txt`, современный браузер с JavaScript и Canvas.
- Локальные FastAPI и Streamlit; запуск из корня проекта: `python launch.py` после `python -m pip install -r requirements.txt`.
- API доступен по адресу http://127.0.0.1:8000, интерфейс — http://127.0.0.1:8501, интерактивная документация API — http://127.0.0.1:8000/docs.
- Для распознавания необходимы интернет, доступ к внешнему API Apilsin и действующий ключ. Локальная LLM и выделенная видеокарта не требуются.
- Ключ задаётся на сервере через `APILSIN_API_KEY` в окружении или корневом `.env`. Альтернатива — `APILSIN_KEY_FILE`: файл должен содержать ровно один уникальный ключ формата `sk-apilsin-…`. По умолчанию проверяется `Desktop/apikey.json` в домашней папке пользователя.
- Настройки по умолчанию: `APILSIN_BASE_URL=https://api.apilsin.run/v1`, `APILSIN_MODEL=gpt-6.1-sol`, `APILSIN_TIMEOUT=180`, `APILSIN_MAX_TOKENS=8192`. Наличие и доступность выбранной модели зависят от провайдера.

Текст задачи передаётся внешнему провайдеру. Локальным является размещение интерфейса, геометрического ядра и истории, но не весь процесс обработки. Автономного режима правил и автоматического перехода на другой распознаватель нет.

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ И РЕАЛИЗАЦИЯ ]**

1. **Ввод условия.** Поле до 6000 символов, библиотека примеров и кнопка «Построить». API отклоняет пустой ввод и запрещённые управляющие символы.
2. **Распознавание.** Apilsin получает текст, системную инструкцию из `backend/recognition_prompt.md` и JSON Schema ответа. Возвращённый JSON локально проверяется Pydantic; строгий режим JSON Schema у провайдера не используется. Возможны отказ, запрос уточнения и предупреждения.
3. **Объекты и числа.** Схема содержит точки, рисуемые отрезки, фигуры, окружности, ограничения, исходные факты и цели задачи. Имена точек — заглавные латинские буквы с необязательным индексом до 999; допускается до 128 точек и 512 ограничений. Модель преобразует числа в JSON-числа, валидаторы проверяют конечность и предусмотренные диапазоны. Отдельного детерминированного текстового анализатора чисел нет.
4. **Геометрические отношения.** Поддерживаются длины, углы, отношения, равенства, параллельность, перпендикулярность, принадлежность, середины, проекции, биссектрисы и ряд окружностных конструкций. Поддержка определяется схемой и решателем, а не только словесной инструкцией модели. Ответы распознавателя с `circle_center` или `segment_difference` отклоняются как не поддерживаемые точно.
5. **Координаты.** Геометрическое ядро использует SymPy, NumPy и SciPy `least_squares`, проверяет невырожденность и невязки; допустимая максимальная невязка — `2e-5`. При свободных размерах строится один экземпляр. Неудача численного поиска не всегда доказывает математическую невозможность.
6. **Интерактивный чертёж.** Canvas показывает точки с подписями, отрезки, окружности и маркеры ограничений `angle`/`right_angle`. Справа находятся «Объекты и связи»: точки, фигуры и ограничения. Подсветки исходного текста и отдельного редактора схемы в интерфейсе нет.
7. **Управление видом.** Колесо мыши и обработчик pinch меняют масштаб; перетаскивание фона перемещает вид; «Сбросить вид» восстанавливает охват построения. Наличие обработчиков не означает проверку на всех устройствах.
8. **Перемещение точек.** После отпускания точки `/update-point` фиксирует её новые координаты и пересчитывает остальные с сохранением ограничений. При отказе остаётся прежнее подтверждённое решение.
9. **Удаление точек.** Кнопка «Удалить» показывает зависимости и запрашивает подтверждение. `/delete-point` удаляет точку и связанные элементы схемы, затем пересчитывает остаток. Другие точки не удаляются; последнюю точку удалить нельзя. Результат может перестать соответствовать исходному условию, о чём интерфейс предупреждает.
10. **Экспорт.** Отдельные кнопки PNG и SVG создают изображение через Matplotlib; PNG — 300 DPI. Экспортируется подтверждённая геометрия, а не снимок текущего масштаба Canvas. API `/export/{fmt}` дополнительно валидирует координаты.
11. **История.** Успешные вызовы `/solve` сохраняются в локальную SQLite `data/history.sqlite3`. История открывается без повторного распознавания. Перемещения и удаления отдельно не сохраняются.

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

GeoGebra и Desmos Geometry предлагают инструменты интерактивной геометрии. Основной сценарий данного проекта — первоначальный чертёж из текстового условия с последующей проверкой и экспортом. По широте ручных построений приложение не заменяет универсальные системы динамической геометрии. Ручное построение остаётся альтернативой и способом проверки результата.

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ ]**

- **Python / FastAPI / Uvicorn** — серверное API.
- **Apilsin / Requests** — внешнее распознавание текста через `/chat/completions`.
- **Pydantic** — схема и валидация ответа модели и запросов.
- **SymPy / NumPy / SciPy** — численное геометрическое ядро.
- **Streamlit / JavaScript Canvas / CSS** — интерфейс и интерактивность.
- **Matplotlib** — экспорт PNG/SVG.
- **SQLAlchemy / SQLite** — локальная история.
- **unittest / Streamlit AppTest / unittest.mock** — имеющиеся офлайн-регрессии удаления точек и подтверждения в интерфейсе, файл `tests/test_point_deletion.py`. Запуск: `python -m unittest discover -s tests -v`.

Ollama и Natasha в текущем коде не используются. `.env`, локальная история и Python-кеши исключены из Git.

1. Разделение frontend/backend и формальная схема геометрии.

Этот перечень описывает состав реализации, а не подтверждает сроки разработки или полноту тестового покрытия.

**[ ВОЗМОЖНЫЕ РИСКИ И ОГРАНИЧЕНИЯ ]**

- Языковая модель может пропустить связь, неверно интерпретировать число или добавить лишнее условие. Валидация схемы и невязок не доказывает соответствие исходному тексту.
- Системная инструкция требует отделять цели доказательства от исходных данных, но отдельного независимого смыслового контролёра нет.
- Возможны несколько допустимых конфигураций, зависимость численного поиска от начального приближения и отказ при существующем решении.
- Нет универсального представления произвольных дуг, площадей, стереометрии и алгебры; нет доказательств и поиска ответа на любой вопрос задачи.
- Распознавание зависит от доступности, лимитов, стоимости и качества внешнего API. Отсутствие ключа и ошибки провайдера возвращаются как 503; ошибки данных и построения обычно как 422.
- Не следует отправлять конфиденциальные условия без учёта передачи Apilsin. Ключи нельзя включать в Git.
- Нет авторизации и специальных лимитов для публичного хостинга. История содержит пользовательский текст и требует защиты локальных файлов.
- Изменения чертежа не записываются в историю; отредактированный результат нужно экспортировать до закрытия сессии.
