# Пользовательские сценарии для проекта «Построитель чертежей для школьной планиметрии»

### Группа: 10И2
### Электронная почта: brshakurov@edu.hse.ru
### ТГ: @shakurov_bulat

Сценарии текущей реализации. Интерфейс и геометрическое ядро работают локально, распознавание текста выполняется внешней языковой моделью через API. Поддержка произвольного условия не гарантируется.

**[ ПОДГОТОВКА К РАБОТЕ ]**

1. **Пользователь устанавливает** Python и зависимости из корня проекта:
   ```sh
   python -m pip install -r requirements.txt
   ```
2. **Пользователь задаёт** адрес и ключ внешнего API в окружении или создаёт корневой `.env` по примеру `.env.example`:
   ```dotenv
   LLM_BASE_URL=https://api.example.com/v1
   LLM_API_KEY=<ваш ключ>
   LLM_MODEL=gpt-6.2-sol
   ```
   В примере нужно подставить адрес своего API и ключ. Ключ нельзя публиковать. `.env` исключён из Git. Другую доступную модель можно указать через `LLM_MODEL`; выбирать модель в интерфейсе нельзя.
3. **Вместо ключа в окружении или `.env` пользователь может указать** `LLM_KEY_FILE` — путь к текстовому файлу, содержащему только ключ. `LLM_API_KEY` имеет приоритет.
4. **Пользователь запускает** `python launch.py` и открывает http://127.0.0.1:8501. API и его документация находятся на http://127.0.0.1:8000/docs. `Ctrl+C` останавливает оба дочерних процесса.
5. **Система запускает** FastAPI и Streamlit на `127.0.0.1`. Для новых распознаваний нужны интернет и доступ к внешнему API; Ollama и локальная видеокарта не нужны. Автономного режима правил нет.
6. **После изменения серверных настроек пользователь перезапускает** приложение. Дополнительные переменные: `LLM_TIMEOUT`, `LLM_MAX_TOKENS` и `LLM_STREAM`; их значения по умолчанию описаны в [описании проекта](final_bshakurov_application.md).

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 1: ВВОД УСЛОВИЯ ]**

- **Пользователь вводит** условие в поле «Условие задачи» либо выбирает задачу в боковой «Библиотеке примеров» и нажимает «Загрузить пример».
- **Пользователь учитывает** уведомление «Текст отправляется внешней языковой модели через API» и нажимает «Построить».
- **Система показывает** «Распознаю условие и проверяю геометрию…» и отправляет текст в `/solve`.
- **Система проверяет** непустой ввод, предел 6000 символов и отсутствие запрещённых управляющих символов. Для пустой строки интерфейс показывает «Поле ввода не может быть пустым» без отправки запроса.
- **Если текст изменён после построения**, система предупреждает, что для обновления нужно нажать «Построить». Автоматической генерации при наборе нет.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 2: РАСПОЗНАВАНИЕ ОБЪЕКТОВ ]**

- **Система отправляет** условие, инструкцию формализатора и схему ответа во внешний API через `/chat/completions`. Предварительного разбора правилами нет.
- **Система проверяет** JSON-ответ локально через Pydantic. Модель должна вернуть статус `ok`, `needs_clarification` или `unsupported`, сообщение, предупреждения и геометрию.
- **При запросе уточнения или неподдержанном условии** интерфейс показывает ошибку с сообщением; отдельного диалога уточнения нет. Пользователь редактирует исходный текст и повторяет запрос.
- **Схема проверяет** уникальность имён точек и предусмотренные ссылки из отрезков, фигур, окружностей и ограничений. Допускаются имена вида `A`, `A1`, `O2`, до 128 точек и 512 ограничений.
- **Система показывает** точки, фигуры и ограничения справа, в блоке «Объекты и связи». Отдельной подсветки обозначений в тексте и редактора JSON в интерфейсе нет.
- **Пользователь сверяет** результат с условием: корректный JSON не доказывает полноту распознавания. Дуги не представлены отдельными универсальными объектами.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 3: ЧИСЛОВЫЕ ПАРАМЕТРЫ ]**

- **Модель преобразует** заданные длины, углы, радиусы, периметры, отношения и тригонометрические значения в числовые поля схемы.
- **Система валидирует** конечность чисел, положительность длин и радиусов, диапазоны углов и другие предусмотренные схемой требования. Математические выражения в числовых полях не исполняются.
- **Пользователь проверяет** значения в списке ограничений. Отдельного детерминированного разбора дробей и корней из исходного текста в текущей версии нет: правильность преобразования зависит от модели.
- **При неверном или неоднозначном числе пользователь уточняет** текст и снова нажимает «Построить». Ручного диалога подстановки числа нет.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 4: ГЕОМЕТРИЧЕСКИЕ ОТНОШЕНИЯ ]**

- **Модель формирует** ограничения параллельности, перпендикулярности, равенства, принадлежности, середины, проекции, биссектрисы и поддержанных окружностных конструкций.
- **Инструкция модели требует** сохранять исходные факты в `givens`, а просьбы найти или доказать — в `targets`, не превращая заключение в предпосылку. Независимой гарантии смысловой корректности такого разделения нет.
- **Система проверяет** схему и численные невязки. Распознавание с `circle_center` или `segment_difference` явно отклоняется: эти ограничения не поддерживаются точно текущим решателем.
- **Пользователь сверяет** отношения справа с исходным условием. Пропущенное при распознавании ограничение может не обнаруживаться решателем.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 5: ГЕНЕРАЦИЯ КООРДИНАТ ]**

- **Система ищет** координаты с помощью геометрического ядра на SymPy, NumPy и SciPy `least_squares`.
- **Система проверяет** невырожденность, предусмотренные явные противоречия и численные невязки; порог решателя — `2e-5`.
- **При свободных размерах система выбирает** один допустимый экземпляр. Он не объявляется единственным и не является доказательством задачи.
- **API возвращает** схему, координаты, отрезки, окружности, фигуры, предупреждения и диагностику времени/невязок.
- **При отказе поиска** пользователь получает ошибку; это не всегда означает математическую невозможность конфигурации.
- **При сбое внешнего API** интерфейс показывает его причину, если она известна. Код 504 означает таймаут подключения, ожидания ответа приложением или ответ 504 от внешнего шлюза. Код 503 используется для недоступности, ошибок настройки и других ошибок провайдера; 502 — для прерванного ответа модели. Некорректный JSON, запрос уточнения, неподдержанное условие и ошибки построения обычно возвращаются с кодом 422. Автоматического переключения модели нет.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 6: ИНТЕРАКТИВНЫЙ ЧЕРТЁЖ ]**

- **Система отображает** на Canvas точки с подписями, отрезки, окружности и маркеры углов для `angle`/`right_angle`.
- **Система подбирает** начальный вид с учётом окружностей, а предупреждения модели выводит над чертежом.
- **Пользователь сверяет** рисунок и список отношений с условием. Отсутствие предупреждений не гарантирует полноту схемы.
- **При ошибке непустого нового запроса** прежнее решение убирается из активного отображения. Пустой ввод лишь вызывает предупреждение и не запускает построение.
- Matplotlib используется для экспорта, а не в качестве интерактивного холста.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 7: МАСШТАБ И ПЕРЕМЕЩЕНИЕ ВИДА ]**

- **Пользователь прокручивает** колесо над холстом для изменения масштаба относительно указателя.
- **Пользователь перетаскивает** фон для перемещения вида.
- **Пользователь нажимает** «Сбросить вид» для охвата всего построения.
- **Система ограничивает** масштаб, не изменяя математические координаты.
- **Canvas обрабатывает** pinch двух указателей. Фактическая работа сенсорных жестов зависит от браузера и устройства; наличие обработчика не заменяет ручную проверку.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 8: ПЕРЕМЕЩЕНИЕ ТОЧЕК ]**

- **Пользователь захватывает** точку и перетаскивает её; во время движения система показывает предварительное локальное положение.
- **После отпускания система возвращает** холст к подтверждённым координатам и отправляет в `/update-point` схему, текущие точки, имя и новые координаты.
- **Сервер проверяет** исходную геометрию, фиксирует выбранную точку и пересчитывает остальные, сохраняя ограничения. Другие вершины тоже могут переместиться.
- **При успехе система обновляет** чертёж, сохраняя контекст и предупреждения; при отказе показывает предупреждение и оставляет прежнее подтверждённое решение.
- Перемещение отдельно в историю не записывается; результат можно экспортировать.

**[ ДОПОЛНИТЕЛЬНЫЙ СЦЕНАРИЙ: УДАЛЕНИЕ ТОЧКИ ]**

- **Пользователь нажимает** «Удалить» рядом с точкой в блоке «Объекты и связи». Для единственной оставшейся точки кнопка отключена.
- **Система показывает** подтверждение «Удалить точку …?», список связанных отрезков, фигур, окружностей и ограничений, а также удаляемые исходные факты и цели, если они найдены.
- **Пользователь выбирает** «Отмена», чтобы оставить чертёж, или «Подтвердить», чтобы отправить запрос `/delete-point`.
- **Сервер удаляет** точку и связанные элементы схемы, очищает зависимости и пересчитывает оставшуюся геометрию, по возможности сохраняя её текущие координаты. Другие точки не удаляются.
- **При успехе система обновляет** рисунок и предупреждает, что ручное изменение может не соответствовать исходному условию. При отказе остаётся прежний чертёж.
- Удаление в историю не записывается. Отдельной кнопки отмены уже подтверждённого удаления нет; исходное сохранённое построение можно снова открыть из истории.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 9: ЭКСПОРТ PNG И SVG ]**

- **Пользователь нажимает** «Скачать PNG» или «Скачать SVG» под холстом; отдельного меню выбора формата нет.
- **Система формирует** изображение Matplotlib из подтверждённой геометрии, а не снимок текущего zoom/pan. PNG имеет 300 DPI.
- **Браузер скачивает** `geometry_drawing_YYYYMMDD_HHMMSS.png` или `.svg`.
- **При отдельном вызове API `/export/{fmt}`** сервер валидирует координаты и отклоняет нарушение ограничений. Кнопки интерфейса формируют экспорт непосредственно, без этого HTTP-запроса.
- При проблемах сохранения пользователь проверяет разрешения браузера и каталог загрузок: стандартная кнопка Streamlit не гарантирует перехват отказа записи файла на устройстве.

**[ ДОПОЛНИТЕЛЬНЫЙ СЦЕНАРИЙ: ИСТОРИЯ ПОСТРОЕНИЙ ]**

- **Система сохраняет** успешную генерацию `/solve`, исходный текст и результат в `data/history.sqlite3`. Перемещения и удаления исходную запись не обновляют.
- **Пользователь нажимает** «Обновить историю», выбирает запись и нажимает «Открыть построение». API выдаёт до 30 последних записей.
- **Система восстанавливает** текст и сохранённый чертёж без нового обращения к внешнему API.
- **Если история недоступна**, интерфейс показывает предупреждение или ошибку открытия. Ошибка записи истории после успешного построения не блокирует работу с полученным результатом и его экспорт.
- История исключена из Git, но содержит пользовательские условия. Приложение не предоставляет авторизацию и не предназначено для публикации без дополнительных мер защиты.

**[ ПРОВЕРКА РЕАЛИЗАЦИИ ]**

Имеющиеся офлайн-регрессии запускаются из корня командой `python -m unittest discover -s tests -v`. Они проверяют удаление точек, очистку зависимостей, отказы и подтверждение/отмену в Streamlit через AppTest с подменой сетевых запросов. Это не полная проверка распознавания через внешний API, браузерных жестов или всех геометрических конструкций.
