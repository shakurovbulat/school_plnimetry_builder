# Пользовательские сценарии для проекта "Построитель чертежей для школьной планиметрии"

### Группа: 10И2
### Электронная почта: brshakurov@edu.hse.ru
### ТГ: @shakurov_bulat

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 1: ВВОД УСЛОВИЯ ЗАДАЧИ НА ЕСТЕСТВЕННОМ ЯЗЫКЕ ]**

* **Пользователь вводит** текст геометрической задачи в специальное интерактивное текстовое поле на главном экране веб-интерфейса.
* **Пользователь нажимает** кнопку «Сгенерировать чертёж» для отправки введённых данных на серверную часть приложения.
* **Система валидирует** полученную текстовую строку на соответствие минимальным требованиям длины и отсутствие запрещённых символов.
* **Система отправляет** валидированный текст задачи через REST API запрос на бэкенд-сервис, реализованный на FastAPI.
* **Система запускает** внутренний процесс лингвистического анализа текста с привлечением специализированных библиотек.
* **Система информирует** пользователя с помощью анимированного индикатора загрузки о том, что текст успешно принят в обработку.
* **Система выводит** понятное предупреждение «Поле ввода не может быть пустым», если пользователь отправил пустую строку.
* **Система предлагает** пользователю скопировать один из готовых шаблонов задач, если введённый текст не поддаётся базовой валидации.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 2: РАСПОЗНАВАНИЕ ГЕОМЕТРИЧЕСКИХ ОБЪЕКТОВ ]**

* **Система анализирует** синтаксическую структуру текста для автоматического поиска заглавных латинских букв, обозначающих геометрические точки.
* **Система сопоставляет** найденные буквенные токены с конкретными фигурами (например, распознаёт словосочетание «треугольник ABC» как набор точек и отрезков).
* **Система выделяет** в тексте упоминания более сложных геометрических сущностей, таких как окружности, дуги, радиусы и описанные многоугольники.
* **Система формирует** предварительный упорядоченный список всех обнаруженных объектов внутри математического модуля SymPy.
* **Система подсвечивает** в интерфейсе Streamlit извлечённые геометрические термины для обеспечения визуального контроля со стороны пользователя.
* **Система запрашивает** у пользователя повторный ввод или уточнение, если имена точек в текстовом условии дублируются или противоречат друг другу.
* **Система выводит** сообщение об ошибке «Не удалось распознать геометрические фигуры на чертеже», если в тексте полностью отсутствуют ключевые объекты.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 3: РАСПОЗНАВАНИЕ ЧИСЛОВЫХ ПАРАМЕТРОВ ]**

* **Система сканирует** текст планиметрической задачи на предмет наличия любых числовых значений, мер длин или градусов.
* **Система связывает** обнаруженные числа с конкретными геометрическими объектами (например, привязывает длину к отрезку или градус к углу).
* **Передает** извлечённые пары в формате «объект — числовой параметр» в геометрическое ядро для дальнейшего расчёта системы уравнений.
* **Система проверяет** корректность числовых данных на соответствие законам геометрии (например, значение угла должно строго лежать в диапазоне от 0 до 180 градусов).
* **Система отображает** полный список всех успешно распознанных величин и параметров в удобной боковой панели веб-интерфейса.
* **Система сигнализирует** о критической ошибке ввода, если к какому-либо отрезку или углу привязано отрицательное или нулевое значение.
* **Система предлагает** пользователю ввести пропущенный числовой параметр вручную, если автоматическая привязка в тексте оказалась неоднозначной.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 4: РАСПОЗНАВАНИЕ ГЕОМЕТРИЧЕСКИХ ОТНОШЕНИЙ ]**

* **Система ищет** в тексте условия ключевые слова-маркеры геометрических отношений, такие как «параллелен», «перпендикулярен», «равен», «пересекаются».
* **Система связывает** пары геометрических объектов (например, две прямые линии) определённым типом выявленного логического отношения.
* **Система накладывает** строгие математические ограничения на будущие координаты объектов в ядре SymPy в соответствии с правилами геометрии.
* **Система проверяет** построенный граф связей на логическую непротиворечивость (например, прямая не может быть одновременно параллельна и перпендикулярна другой прямой).
* **Система выводит** текстовое сообщение о математическом конфликте исходных условий, если обнаруженные логические связи явно противоречат друг другу.
* **Система подсвечивает** зелёным цветом обнаруженные связи в интерактивном логе разбора задачи для наглядности.
* **Система игнорирует** незнакомые речевые обороты, сохраняя общую базовую структуру чертежа и уведомляя пользователя о пропущенных деталях.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 5: АВТОМАТИЧЕСКАЯ ГЕНЕРАЦИЯ КООРДИНАТ ОБЪЕКТОВ ]**

* **Система инициализирует** расчётный модуль SymPy для автоматического составления и решения системы алгебраических уравнений на плоскости.
* **Система вычисляет** точные декартовы координаты для каждой вершины, центра окружности и точки пересечения, удовлетворяющие всем заданным ограничениям.
* **Система применяет** быстрые численные методы оптимизации, если точное аналитическое решение системы координат занимает слишком много процессорного времени.
* **Система масштабирует** полученный массив вычисленных координат, чтобы будущий чертёж гармонично и полностью вписывался в стандартную область просмотра.
* **Система трансформирует** финальные координаты в структурированный JSON-формат для отправки по API обратно в клиентскую часть Streamlit.
* **Система останавливает** вычисления и выдаёт ошибку «Фигура с заданными свойствами не существует», если в процессе расчёта нарушено неравенство треугольника.
* **Система генерирует** случайное, но полностью геометрически корректное расположение объектов, если в тексте задачи отсутствуют жёсткие числовые размеры.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 6: ПОСТРОЕНИЕ ИНТЕРАКТИВНОГО ЧЕРТЕЖА ]**

* **Система получает** с серверного бэкенда валидный JSON-пакет, содержащий рассчитанные координаты точек, прямых, отрезков и окружностей.
* **Система генерирует** графический объект с помощью встроенных возможностей библиотеки визуализации Matplotlib на основе полученных данных.
* **Система отрисовывает** все необходимые геометрические линии, дуги углов, маркеры перпендикулярности и текстовые подписи латинских названий точек.
* **Система внедряет** сгенерированный график Matplotlib в веб-интерфейс Streamlit с помощью специализированного интерактивного контейнера.
* **Система адаптирует** толщину линий, размеры маркеров и шрифты под текущее разрешение экрана и масштаб устройства пользователя.
* **Система выводит** в интерфейс уведомление «Ошибка визуализации чертежа», если переданные сервером координатные данные были повреждены при передаче.
* **Система автоматически обновляет** холст с чертежом при успешном завершении любого нового цикла генерации или изменения текста задачи.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 7: МАСШТАБИРОВАНИЕ И ПЕРЕМЕЩЕНИЕ ЧЕРТЕЖА ]**

* **Пользователь использует** колесо компьютерной мыши или стандартный жест Pinch-to-zoom на тачпаде над областью отображения интерактивного чертежа.
* **Система пересчитывает** динамические границы отображения координатных осей в объекте Matplotlib в режиме реального времени.
* **Пользователь зажимает** левую кнопку мыши в любой точке холста и перемещает курсор для сдвига всей плоскости чертежа.
* **Система сдвигает** фокус отображения графического холста вслед за траекторией движения указателя мыши пользователя.
* **Пользователь нажимает** выделенную кнопку «Сбросить вид» на панели управления для возврата к исходному автоматическому масштабу.
* **Система возвращает** геометрический чертёж в центральное положение с оптимальным охватом и видимостью всех существующих элементов.
* **Система блокирует** дальнейшее удаление или приближение холста, если масштаб становится слишком мелким или чрезмерно крупным для восприятия.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 8: РЕДАКТИРОВАНИЕ ПОЛОЖЕНИЯ ТОЧЕК ВРУЧНУЮ ]**

* **Пользователь кликает** левой кнопкой мыши по маркеру конкретной точки на интерактивном чертеже для её выделения и захвата.
* **Система подсвечивает** выбранную точку ярким цветом и переводит графический холст в режим динамического изменения геометрии.
* **Пользователь перетаскивает** зажатую точку в новое произвольное место на координатной плоскости с помощью движения мыши.
* **Система пересчитывает** текущее положение всех зависимых объектов (медиан, высот, связанных отрезков), стремясь сохранить заданные в условии логические связи.
* **Пользователь отпускает** левую кнопку мыши, тем самым фиксируя финальное положение выбранной геометрической точки на экране.
* **Система отправляет** изменённые координаты через REST API на сервер для полной актуализации внутренней математической модели задачи.
* **Система выдает** предупреждающий визуальный сигнал и возвращает точку на место, если пользователь пытается переместить её вопреки жёстким законам геометрии.

**[ ФУНКЦИОНАЛЬНОЕ ТРЕБОВАНИЕ 9: ЭКСПОРТ РЕЗУЛЬТАТА В PNG И SVG ]**

* **Пользователь нажимает** на кнопку «Экспорт чертежа», расположенную непосредственно под интерактивным графическим холстом.
* **Система открывает** компактное выпадающее меню с предложением выбрать формат файла: растровый (PNG) или векторный (SVG).
* **Пользователь выбирает** необходимый ему формат графического файла в зависимости от дальнейших целей использования чертежа.
* **Система вызывает** внутреннюю функцию сохранения библиотеки Matplotlib с точным указанием выбранного расширения и высокого разрешения DPI.
* **Система инициирует** стандартный браузерный процесс скачивания готового медиафайла на локальное электронное устройство пользователя.
* **Система присваивает** скачиваемому файлу уникальное осмысленное имя по шаблону даты и названия задачи (например, `geometry_drawing_2026.svg`).
* **Система выводит** текстовое всплывающее уведомление «Ошибка скачивания», если у веб-браузера отсутствуют права на запись файлов в память устройства.
