**[ НАЗВАНИЕ ПРОЕКТА ]**

«Построитель чертежей для школьной планиметрии».

**[ ПРОБЛЕМНОЕ ПОЛЕ ]**

Перенос текстового условия в аккуратный чертёж требует времени и понимания взаимного расположения объектов. Ошибки в обозначениях, длинах и отношениях мешают дальнейшему решению задачи. Проект помогает получить первоначальную визуализацию и проверить её геометрические ограничения, оставляя пользователю контроль над правильностью распознавания текста.

Приложение не является универсальным решателем: оно не выдаёт доказательство и не гарантирует понимание любого школьного условия.

**[ ЗАКАЗЧИК / ПОТЕНЦИАЛЬНАЯ АУДИТОРИЯ ]**

- Учащиеся 7–11 классов, изучающие планиметрию.
- Учителя математики и репетиторы, готовящие иллюстрации.
- Пользователи, которым нужен экспорт школьного чертежа в цифровом виде.

**[ АППАРАТНЫЕ / ПРОГРАММНЫЕ ТРЕБОВАНИЯ ]**

Текущая версия разворачивается локально, а не на общедоступном сервере:

- Python 3.10 и зависимости из `requirements.txt`.
- Современный браузер с JavaScript и Canvas.
- Ollama и установленная модель, по умолчанию `deepseek-coder-v2:16b`.
- Для модели по умолчанию рекомендуется видеокарта с 12 ГБ VRAM; скорость зависит от оборудования. Возможность CPU/offload определяется Ollama.
- Интернет нужен для первоначальной установки зависимостей и модели. При локальном адресе Ollama обработка не требует облачного API.
- Для явного режима правил `PARSER_MODE=rules` Ollama не требуется; распознавание ограничено поддержанными правилами.

Проверки выполнялись на Windows и Python 3.10. Инструкции запуска: `README.md`. Сервисы слушают `127.0.0.1`: API — порт 8000, интерфейс — 8501.

**[ ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ И РЕАЛИЗАЦИЯ ]**

1. **Ввод условия.** Текстовое поле, готовые примеры; API отклоняет пустой ввод, управляющие символы и текст длиннее 6000 символов.
2. **Распознавание объектов.** Правила и структурированный ответ Ollama выделяют точки, отрезки, фигуры и окружности. Pydantic проверяет имена и ссылки.
3. **Распознавание чисел.** Поддержанные формулировки длин, углов, отношений, радиусов, периметров и тригонометрических значений; нормализация дробей и корней без выполнения пользовательского кода.
4. **Геометрические отношения.** Параллельность, перпендикулярность, равенства, середины, принадлежность, проекции, биссектрисы и ряд окружностных конструкций преобразуются в ограничения.
5. **Координаты.** Геометрическое ядро ищет невырожденное численное решение и проверяет невязки. Явно невозможные или неподдержанные конфигурации отклоняются; отказ не подменяется произвольным рисунком.
6. **Интерактивный чертёж.** Canvas показывает точки, подписи, отрезки, окружности и маркеры заданных углов; рядом выводятся распознанные параметры.
7. **Управление видом.** Масштабирование колесом, pan и сброс вида; реализована обработка pinch, физический сенсорный жест ещё требует ручной проверки.
8. **Редактирование.** После отпускания перетаскиваемой точки сервер пересчитывает зависимую геометрию. Невыполнимое перемещение отклоняется с сохранением прежнего рисунка.
9. **Экспорт.** PNG (300 DPI) и SVG через Matplotlib, отдельные кнопки скачивания и API.
10. **История.** Успешные генерации сохраняются в локальную SQLite и повторно открываются через боковую панель. Изменения точек отдельно не сохраняются.

**[ ПОХОЖИЕ / АНАЛОГИЧНЫЕ ПРОДУКТЫ ]**

GeoGebra и Desmos Geometry предоставляют инструменты интерактивной геометрии. Данный проект сосредоточен на другом основном сценарии: подготовке первоначального чертежа из русскоязычного условия с последующей проверкой и экспортом. Он не заменяет универсальные системы динамической геометрии и уступает им по широте ручных построений.

Ручное построение остаётся альтернативой и способом проверки результата. Преимущество приложения — быстрое получение цифровой иллюстрации для поддержанного условия, а не гарантированное сокращение времени на каждой задаче.

**[ ИНСТРУМЕНТЫ РАЗРАБОТКИ ]**

- **Python / FastAPI / Uvicorn** — HTTP API.
- **Ollama / Requests** — локальный структурированный разбор; модель получает предварительную схему правил. Конфликт явных числовых фактов отклоняется, поддержанные конструкции правил имеют приоритет. Ошибка Ollama возвращает 503, без скрытого fallback.
- **Pydantic** — формальная схема и валидация данных.
- **SymPy / NumPy / SciPy least_squares** — элементарные построения, координаты и невязки. Это не общее точное символьное решение.
- **Streamlit / JavaScript Canvas** — интерфейс и интерактивность.
- **Matplotlib** — PNG/SVG, не интерактивный холст.
- **SQLAlchemy / SQLite** — локальная история.
- **unittest / pytest / Playwright / Node.js / Ruff** — регрессии, браузерные и компонентные проверки, единый стиль.

Natasha не используется. Отдельный интерфейс отладки удалён из актуальной версии. Секреты `.env`, история, окружения и генерируемые отчёты исключены из Git.

**[ ВОЗМОЖНЫЕ РИСКИ И ОГРАНИЧЕНИЯ ]**

- Неоднозначный текст или неполное описание исходного рисунка.
- Потерянные при распознавании связи: численно корректная схема может быть неполной.
- Несколько допустимых конфигураций и неоднозначность пересечений.
- Невозможность численного поиска найти решение за отведённое время не всегда доказывает противоречивость задачи.
- Зависимость LLM от модели, аппаратуры и доступной памяти.
- Не реализованы универсальные доказательства, произвольные дуги и все школьные конструкции.
- Нет авторизации и лимитов для публичного хостинга; приложение предназначено для локальной работы.
- История содержит пользовательские условия и требует обычной защиты локальных файлов.
